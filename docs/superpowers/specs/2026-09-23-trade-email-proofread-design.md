# 英文商务外贸邮件审校技能设计

日期：2026-09-23

## 目的

提供一个 Cursor 技能，审校用户给出的英文商务外贸邮件。技能只做这一次语言审校。

## 技能定位

- 名称：`trade-email-proofread`
- 路径：`.cursor/skills/trade-email-proofread/`
- 文件：
  - `SKILL.md`：审校流程与输出格式。正文使用中文。
  - `reference.md`：外贸中式英语模式，以及本文「验收」中的样例。审校开始前读取。
- 不设置 `disable-model-invocation`，以便在匹配场景下自动启用。
- `description` 使用第三人称，同时写明用途和触发条件，并包含这些触发词：英文邮件、外贸、拼写、语法、用词、中式英语、proofread、spelling、grammar。

`description` 使用下面这段原文：

```
Reviews the subject and body of an English business or foreign-trade email for spelling, grammar, punctuation, collocation, and Chinglish. Use when the user asks to check or proofread the language of an English trade email, quotation, or inquiry, including 英文邮件, 外贸, 拼写, 语法, 用词, or 中式英语. Reports confirmed issues and uncertain items in Chinese, with the English sentence and a single-span fix.
```

## 审校对象

审校主题和正文。

以下内容不进入检查，不出现在「确定错误」或「待确认」中：

- 签名档。从正文末尾向前看，下面两种行及其后的内容都是签名：单独一行的 `--`；单独成行且整行只有敬语的行，敬语为 `Best regards`、`Kind regards`、`Regards`、`Sincerely`、`Thanks`、`Thank you`，可以带逗号。正文开头或句中的 `Thank you for ...` 仍属于正文。
- 已识别的引用历史。以 `>` 开头的行，或包含 `On ... wrote:`、`-----Original Message-----`、`Forwarded message` 的区块，以及该区块之后的全部内容。
- 专名，保持原样，即使看起来像拼写错误。封闭清单：
  - 单号、发票号、合同号
  - 型号、SKU
  - 价格、币种
  - 公司名、人名
  - Incoterms，如 FOB、CIF、EXW、CFR、DDP
  - 电子邮箱、网址、电话号码

专名周围的句子仍要检查。修改建议不得改动专名中的任何一个字符。数量、交期和承诺留在句子里接受检查；改法若会改变这些事实，或会改变价格、产品含义，放入待确认。

一次只审一封邮件。用户同时给出多封时，先请用户指定一封。

## 审校流程

1. 切开主题和正文，并按上一节排除签名和引用历史。
2. 标出专名。
3. 只按五个类别检查。同一错误跨度只归一个类别，归类优先级从高到低：
   1. 中式英语：冠词误用、时态与时间状语冲突、介词误用、中英误用词
   2. 语法：一致关系、动词形式、句子结构
   3. 标点
   4. 用词搭配：词存在，但搭配不成立，且不属于中式英语
   5. 拼写：单词拼错，且该词不是专名
4. 判定把握。
   - 放入「确定错误」：改法只有一种，且不改变数量、价格、交期、承诺或产品含义。
   - 放入「待确认」：改法不止一种；改法可能改变数量、价格、交期、承诺或产品含义；或无法判断是中式英语还是行业惯用语。
5. 按输出格式出报告。不附整封改写稿。用户同时要求重写全文或评价语气、礼貌、商务策略时，仍然只输出这两栏。

## 输出格式

报告固定为两栏，顺序是「确定错误」，然后「待确认」。每一栏都要出现。某一栏没有条目时，该栏只写对应的空状态句。

空状态原文：

- 确定错误：`未发现确定错误`
- 待确认：`无待确认项`

有条目时，每条固定这五项，顺序不变：

1. 位置：`主题`，或 `正文第 N 句`
2. 类别：`拼写`、`语法`、`标点`、`用词搭配`、`中式英语` 之一
3. 原句：英文整句
4. 改法：同一句英文，只改这一处。同一句里的其他错误保持原样
5. 说明：中文，一到两句。待确认的说明必须写明拿不准的原因

同一句里位置不同的错误分成多条。同一个错误跨度只出现一次。各栏内部按邮件出现顺序排列，主题条目排在正文条目之前。

正文第 N 句从 1 起编。一句以 `.`、`?` 或 `!` 结束。小数点、型号中的点，以及 `Mr.`、`Ms.`、`No.`、`Inc.` 不作为句界。单独成行、没有句末标点的问候语单独计为一句。中文句子不计入 N，英文句子按出现顺序连续编号。主题整行算一个位置，不按句拆开。

条目格式：

```
## 确定错误

1. 位置：正文第 1 句
   类别：语法
   原句：We has prepared the samples.
   改法：We have prepared the samples.
   说明：主语 We 与动词 has 不一致，应使用 have。

## 待确认

无待确认项
```

## 异常与边界

- 没有英文邮件：请用户贴出主题和正文，先不审校。
- 只有正文或只有主题：审现有部分，并写明缺的是主题还是正文。
- 正文是中文：说明本技能只审英文商务邮件，不输出两栏错误列表。
- 中英夹杂：只审英文句子，并写明中文句子已跳过。
- 引用历史和正文分界不清：可疑部分不放入确定错误，在待确认里注明「可能是引用历史」。
- 不评价语气、礼貌或商务策略。

## 验收

对照下表检查技能输出。不另做自动测试程序。样例全文写在 `reference.md`。

| 样例 | 通过标准 |
|---|---|
| 没有语言问题的主题和正文 | 两栏分别为「未发现确定错误」「无待确认项」 |
| 拼写、语法或标点有一处硬错误 | 出现在确定错误，类别正确，改法只动这一处 |
| 冠词、时态、介词或中英误用词 | 类别为「中式英语」，说明用中文 |
| 价格、型号、Incoterms、公司名看起来怪异 | 不进入任一栏 |
| 签名和已识别的引用历史里有明显错误 | 两栏都不出现这些错误 |
| 改法会改变数量、价格、交期、承诺或产品含义 | 只出现在待确认，并写明原因 |
| 只有中文正文 | 说明只审英文，不输出两栏错误列表 |
| 用户要求重写全文 | 仍然只有两栏，没有整封改写稿 |
| 缺少主题或缺少正文 | 审现有部分，并写明所缺部分 |
| 中英夹杂 | 只审英文句子，并写明中文句子已跳过 |
| 引用历史和正文分界不清 | 可疑部分只出现在待确认，说明含「可能是引用历史」 |

## 范围

本规格只覆盖这一个审校技能。不包含代写邮件、跟进策略、模板库、语气改写，也不包含外部语法引擎。
